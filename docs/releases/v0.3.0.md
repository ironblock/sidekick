sidekick v0.3.0 adds classification. `POST /v1/classify` follows vLLM's `/classify` and SGLang's `/v1/classify` field for field, so their clients work unchanged, and it runs text classifiers and zero-shot decision models on the Neural Engine. Two classifiers come with converters and manifests: a validated multilingual sentiment model, and laya, a zero-shot decision model, as a preview.

## Upgrading

- **A model sent to the wrong route is a 400, not a 404.** An embedder's id on `/v1/chat/completions`, or a classifier's on `/v1/embeddings`, now gets a 400 that names the model's task and the route that serves it.
- **Malformed request bodies are a 400 on every route**, in the API's usual error shape (D22 amendment). Invalid JSON, a missing field, a wrong type or a missing JSON content type used to get a plain-text 422 or 415 from the HTTP framework. A body over the size limit is still a 413.
- **A bad model manifest no longer stops everything.** A manifest that doesn't parse or validate, or that repeats another model's id, is skipped with a warning, and the rest of the models directory loads. This applies to `sidekickd`, which used to refuse to start, and to `sk_pool_open` in `libsidekick.dylib`, which used to fail. `/health` lists the skipped manifests with the reason under `skipped_models`, and the new `sk_pool_skipped` returns them to C ABI hosts. `SK_ABI_VERSION` stays 1, because the change is additive; hosts that may run against an older library should look `sk_pool_skipped` up with `dlsym`.
- **Listings are task-aware.** `/v1/models` gives every model a `task`, using Hugging Face's pipeline names (`feature-extraction`, `text-classification`, `zero-shot-classification`, `text-generation`). `/health` lists classifiers separately. The C ABI's `sk_pool_models` and `sk_model_info` still list embedders only.
- **Inference responses carry provenance headers** on `/v1/embeddings`, `/v1/chat/completions` and `/v1/classify`:
  - `sidekick-version`;
  - `sidekick-model`: `<id>@<revision>` when the manifest names its source revision;
  - `sidekick-compute-units`: `cpu_and_ne` for Core ML models, `cpu` for static ones.
- **Rust library users:** the embedder pool is now a generic `ModelPool`, built with `EmbedderPool::embedders` from the registry; `EmbedderPool::new` and `registry()` are gone, and `AppState` has new fields.
- **The release archive includes `THIRD_PARTY_NOTICES.md`**, for the Apache-2.0 code and data that the laya support derives from.

## Classification

- **The contract** is in [docs/design/classify.md](https://github.com/ironblock/sidekick/blob/v0.3.0/docs/design/classify.md), and the decisions behind it are D28. Send `{"model": ..., "input": "text" | ["text", ...]}` and get back `data[{index, label, probs, num_classes}]` and `usage`. `probs` uses transformers' activation for the model, and `use_activation: false` returns raw logits.
- **Every vLLM request field is honored or rejected with a 400, never silently dropped.** That covers `truncate_prompt_tokens` (−1 means the model's maximum), `truncation_side`, `request_id`, `priority`, `padding`, `cache_salt`, `add_special_tokens`, `normalize` and chat-form `messages`. The design doc lists where sidekick deliberately differs from vLLM:
  - `model` is required;
  - truncation keeps `[CLS]` and `[SEP]`.
- **Zero-shot models** take their labels per request as `candidate_labels`, Hugging Face's name. laya also takes `question_type` (`choice`, `score` or `noul`) and optional `instructions`. `calibration: "model"` applies the temperature a model declares; it's off by default.
- **Requests are validated in full before anything runs**, so a bad input in a batch costs no inference. Loading a classifier checks every bucket's artifact first, so a bad one fails the load rather than a later request.
- **Classifiers** are directories with a `classifier.toml`, a separate filename, so older daemons and libraries never read them. Examples are in [examples/classifiers/](https://github.com/ironblock/sidekick/tree/v0.3.0/examples/classifiers).

## Classifier accuracy

The parity suite (D26) now grades classifiers too, in probability space against the model's own fp32 forward: A for a worst-case |Δp| ≤ 0.001, B ≤ 0.005, C ≤ 0.02, D above, and F for a failed hard gate. M1 Max, macOS 27:

| model | CPU | GPU | Neural Engine | ANE ms |
|---|---|---|---|---|
| nlptown-sentiment (5-star reviews, multilingual BERT) | B | A | **B** (worst Δp 0.0026, no decision changes) | 4.2 |
| laya-en (zero-shot decisions, ModernBERT-large), **preview** | D | F | **F** (worst Δp 0.077; 99.81% of 2,612 decisions agree with fp32) | 38 |

- **nlptown-sentiment** passes every gate on every path. Convert it with `tools/convert_bert_classifier.py`.
- **laya-en is a preview.** It fails the suite's bucket-invariance gate on the GPU and the Neural Engine. An input's probabilities move by up to 0.038 on the Neural Engine when the same input runs at the next larger input size, against a 0.001 gate. The graph itself is invariant: the CPU path is exact across sizes, padding changes nothing, and results are deterministic. The loss is fp16 rounding in laya's ModernBERT-large encoder. Its 5 changed decisions on the Neural Engine all had fp32 margins of 0.12 logits or less, so read `probs`, not just `label`, when a decision is close. The fix is being worked on for a point release. Convert it with `tools/convert_laya.py`.

Details, including where laya's loss comes from, are in [docs/MODELS.md](https://github.com/ironblock/sidekick/blob/v0.3.0/docs/MODELS.md#classifiers-v1classify).

## Embeddings

- Unchanged. All five validated embedding models still grade A on the Neural Engine in this release's parity run.
