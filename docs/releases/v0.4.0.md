sidekick v0.4.0 adds reranking. `POST /v1/rerank` follows vLLM (and the Jina shape llama.cpp, LocalAI and Infinity serve), `/v2/rerank` and `/v2/embed` follow Cohere's v2 API, and cross-encoders run on the Neural Engine. It also adds two small embedding models, and a conversion library that makes new models faster to bring up and safer to change.

## Upgrading

- **Classifier loading is stricter.** A classifier artifact with an input its manifest doesn't name is now refused at load, instead of failing every request. Every model converted by this repository's tools names all of its inputs.
- **Rust library users:** these changes are semver-breaking (D29):
  - `sidekick_core::ClassifyTask` has a new variant, `TextRanking`; exhaustive matches must handle it.
  - `sidekick_core::Prepared` has a new public field, `type_ids`.
  - `sidekick_core::manifest::ClassifierIo` has a new public field, `token_type_ids`.
  - Additive: `ClassifyTask::name`, `PairParams`, `Classifier::prepare_pair`, `EmbedLimits`, `Truncate`, `Embedder::embed_with`, `CoremlEmbedder::prepare_with` and `InputBuilder::prepare_pair`.
- The C ABI is unchanged.

## Reranking

- **`POST /v1/rerank` and `POST /rerank`** are vLLM's rerank request and response, field for field: `query`, `documents`, `top_n`, `use_activation`, `truncate_prompt_tokens`, `max_tokens_per_query` and `max_tokens_per_doc`. Results are sorted by score. The one extension is `return_documents`, from Jina and Cohere v1.
- **`POST /v2/rerank`** is Cohere's v2 shape. Its response also carries the fields vLLM's response requires, so clients written for either parse it. Long documents are truncated, keeping the query whole, as Cohere does.
- **`POST /v2/embed`** is Cohere's v2 embed shape over the existing embedders, as vLLM serves it. `input_type` selects the model's query or document prefix, and `embedding_types` covers `float`, `base64`, `binary` and `ubinary`.
- **Fail loudly.** Every field these APIs define is honored or rejected with a 400. Where vLLM's truncation would feed a model a sequence unlike its training, sidekick deviates and documents it: special tokens are always kept, an empty document is still paired with its query, and `/v2/embed`'s `START` truncation keeps the prompt prefix.
- **Rerankers are classifiers.** Each is a `classifier.toml` with `task = "text-ranking"` and, for BERT models, a `token_type_ids` input. `/v1/models` lists them with their task. The contract is in [docs/design/rerank.md](https://github.com/ironblock/sidekick/blob/v0.4.0/docs/design/rerank.md).

## New models

Graded by the parity suite on an M1 Max, macOS 27:

| model | task | Neural Engine | notes |
|---|---|---|---|
| cross-encoder/ms-marco-MiniLM-L6-v2 | reranking | **B** (worst Δp 0.0034, no rank flips) | B on every path |
| sentence-transformers/all-MiniLM-L6-v2 | embeddings | **A** (worst cosine 0.99992) | buckets up to 256, its trained length |
| intfloat/e5-small-v2 | embeddings | **A** (worst cosine 0.99995) | uses its `query:` / `passage:` prefixes |

Rerankers are graded in probability space with the raw score error published beside each grade, and rank flips are checked within each query's documents. Details are in [docs/MODELS.md](https://github.com/ironblock/sidekick/blob/v0.4.0/docs/MODELS.md).

## Conversion tools

- **`tools/sidekick_convert`** is a composable conversion library. A converter combines an architecture backbone (BERT, ModernBERT, Qwen3 decoder), a task head (pooling, classification, reranking) and a fixed-shape interface. Every Neural Engine technique sidekick relies on is a documented module there.
- **The library didn't change any existing artifact.** The existing converters were rebuilt on the library and produce byte-identical models.
- **New converters:** `tools/convert_bert_embedder.py` for any sentence-transformers BERT, and reranker support in `tools/convert_bert_classifier.py`, including an opt-in GELU built from erf.
- **[docs/CONVERTING.md](https://github.com/ironblock/sidekick/blob/v0.4.0/docs/CONVERTING.md)** catalogs the techniques, the gotchas found so far and how to add a model family.
- **An ideal-fp16 simulation**, `sidekick_convert.fp16sim`, measures how much error fp16 arithmetic alone would cause for a model. The reference generator records it, in preparation for grading classifiers against it.
