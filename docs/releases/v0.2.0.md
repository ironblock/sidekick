sidekick v0.2.0 brings the Foundation Models chat tier up to macOS 27, streams chat replies as they're generated, and adds a fifth embedding model validated on the Neural Engine, gte-modernbert-base. It also publishes a graded accuracy for every embedding model on every compute path.

## Upgrading

- **Chat requests that depend on unsupported features are rejected** (D22). sidekick used to answer them as if the parameter weren't there. Now these get HTTP 400:
  - `n` > 1;
  - non-empty `tools` or `functions`;
  - a `tool_choice` or `function_call` that requires or names a tool;
  - `logprobs: true`, or `top_logprobs` > 0.

  The defaults OpenAI SDKs send still work: `n: 1`, empty tools, `tool_choice` `"auto"` or `"none"`, and `logprobs: false`.
- **Re-convert EmbeddingGemma** with this release's `tools/convert_embeddinggemma.py`. Its MLP precision rewrite raises ANE parity from 0.9905 to 0.99999 (D17). Artifacts converted earlier keep working, less accurately.
- **Core ML models with more than one enumerated input shape are refused on macOS 27** (D27). `sidekickd` and `libsidekick.dylib` now reject such a model at load rather than risk an abort no one can catch. The per-bucket static artifacts that this repo's converters produce are unaffected.
- **Building from source needs the macOS 26.4 SDK or newer** (Xcode 26.4+). Build with Xcode 27 to get the macOS 27 features below. `sidekickd --version` and `/health` report the SDK a binary was built with.

## Chat (Foundation Models)

- On macOS 27 (D21), when built with the macOS 27 SDK, as the release binaries are:
  - Token usage is real, including `prompt_tokens_details.cached_tokens` when a follow-up reuses its session.
  - `/health` reports the model variant (for example AFM 3 Core), its real context size, and what it supports.
  - Errors are mapped by type:

    | error | response |
    |---|---|
    | over-long prompt | 400, with real token counts (it had become a 500 on macOS 27) |
    | guardrail refusal | 400 `content_filter` |
    | rate limit | 429 with `Retry-After` |
    | transient failure | one retry, then 503 |
- `finish_reason` is `"length"` when `max_tokens` cuts a reply.
- `stop` sequences are honored, up to four. They used to be ignored. They can't be combined with `json_schema`.
- **Streaming is real** (D23): `stream: true` sends text as the model generates it. A client that disconnects stops generation. Schema-constrained replies still arrive whole.

## Embeddings

- **gte-modernbert-base is validated on the ANE** (D25). Convert it with `tools/convert_gte_modernbert.py`. ModernBERT had been documented as ANE-incompatible. The cause was Core ML's fused attention op, which ignores its mask on the ANE when the mask comes from outside the attention's own ANE step; explicit attention avoids it.
- **Confidence grades** (D26). A parity suite runs 51 adversarial inputs through sidekick's own embedding code on the CPU, GPU and ANE paths, and grades each path against the model as published. ANE grades (M1 Max, macOS 27):

  | model | grade | worst cosine vs fp32 |
  |---|---|---|
  | bge-small-en-v1.5 | A | 0.99997 |
  | embeddinggemma-300m | A | 0.99999 (re-converted) |
  | gte-modernbert-base | B | 0.9994 |
  | F2LLM-v2-160M | B | 0.9997 |
  | LFM2.5-Embedding-350M | D | 0.954 |

  See `docs/MODELS.md` for the method and the per-path numbers.
- `ane_check` judges ANE eligibility from Core ML's compute plan instead of a latency ratio (D24). It also checks that pad content can't change the output, which catches a dropped attention mask.

## Tools (in the repository, not the release archive)

- `tools/probe_activations.py` triages a candidate model's fp16 range before any conversion.
- `tools/parity_reference.py` and the `parity` example in `sidekick-embed` make up the parity suite.
- `tools/repro_sdpa_mask.py` reproduces the fused-attention mask drop standalone. Its `--check` flags affected models from their compute plan.
- The ModernBERT and LFM2.5 converters take negative-control flags, `--attn sdpa` and `--no-pad-zeroing`, to rebuild known-bad artifacts.

## Known issues

- **LFM2.5-Embedding-350M loses accuracy on the ANE** on URL- and delimiter-heavy input: worst cosine 0.954, and similarity scores can shift by up to 0.19. Its CPU path is exact. An investigation is under way.
- **Core ML's compile caches can grow large and break compute plans.** Core ML caches compiled models per executable in `~/Library/Caches/<executable>/com.apple.e5rt.e5bundlecache`. Compiling many models, as `ane_check` and the parity suite do, can grow a cache to tens of GB. A broken entry makes compute plans for that artifact path unreadable; both tools report it. The caches are safe to delete.

## Artifacts

`sidekick-v0.2.0-aarch64-apple-darwin.tar.gz` contains `sidekickd`, `libsidekick.dylib`, `sidekick.h`, these notes and the integration docs. It needs Apple Silicon with macOS 26 or later, and is built with the macOS 27 SDK and verified to launch on macOS 26. The `.sha256` file holds its checksum.
