sidekick v0.3.1 makes the laya-en preview classifier far more accurate on the Neural Engine, and fixes embedding models whose tokenizer pads every input to a fixed length.

## Upgrading

- **Re-convert laya-en** with this release's `tools/convert_laya.py` to get its accuracy fix. Artifacts converted with 0.3.0 keep working, less accurately.
- No API or configuration changes.

## laya-en: decisions hold on the Neural Engine

The ANE's loss was Core ML's native `gelu` op, which is coarse on the Neural Engine in the first layers of laya's ModernBERT-large encoder. The converter now builds every GELU from erf, exact in fp32, and fails if a native `gelu` op survives (D28 amendment). On laya's 2,612-case corpus:

| path | changed decisions | worst Δp (p99) |
|---|---|---|
| Neural Engine | 5 → 1 | 0.077 → 0.039 (0.030 → 0.016) |
| GPU | 0 → 0 | 0.030 → 0.025 |

The remaining change of decision had an fp32 margin of 0.057 logits, and latency rises by 1–7%. laya-en stays a preview: an ideal fp16 engine still moves its probabilities by up to 0.026, so no fp16 path can reach the suite's top grades on the current scale, and it still fails the bucket-invariance gate on the GPU and Neural Engine (0.011 and 0.027, against 0.001). A softmax written as one matmul makes the Neural Engine exactly bucket-invariant; adopting it comes with a change to how classifiers are graded, in a later release. Details are in [docs/MODELS.md](https://github.com/ironblock/sidekick/blob/v0.3.1/docs/MODELS.md#classifiers-v1classify) and the D28 amendment.

## Fixes

- **Embedders no longer embed a tokenizer's padding as text.** Some published `tokenizer.json` files pad every input to a fixed length (all-MiniLM-L6-v2, all-MiniLM-L12-v2 and gte-small pad to 128). sidekick read those pads as real tokens, so each input was embedded together with its padding. Both embedder backends now turn the tokenizer's padding off at load. No model validated so far was affected.

## Tools

- `tools/repro_cpu_reduce_max.py` reproduces a Core ML defect on macOS 27: on the CPU, `reduce_max` and `reduce_min` over 256 or more elements return max(x, 0), which is wrong for rows whose maximum is negative. `--check` lists a model's affected reductions. Taking the maximum in blocks of 128 avoids it on every compute unit.
- `tools/measure_classifier.py` measures bucket invariance the way the parity suite gates it.
