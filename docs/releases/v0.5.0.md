sidekick v0.5.0 adds three zero-shot decision models and two new zero-shot formats, lets a model choose where it runs, and grades classifiers against what fp16 itself allows. laya-en is no longer a preview.

## Upgrading

- **Re-convert laya-en** with this release's `tools/convert_laya.py` to get exact bucket invariance on the Neural Engine. Its softmax is now built from one matmul. Artifacts converted with 0.4 keep working.
- **Manifests can name their compute units** (D31). The new optional `compute_units` key in `classifier.toml` and `manifest.toml` takes `cpu_and_ne` (the default, unchanged), `cpu_and_gpu`, `cpu_only` or `all`. `sidekick-compute-units` and `/v1/models` report it. sidekick 0.4 ignores the key and loads on the Neural Engine.
- **`/v1/models` lists each classifier's `required` request fields** (D30).
- **`multi_label: false` is accepted on every classifier** as the default form. `multi_label: true` is a 400 except on gliner2-format models.
- No breaking API changes. The C ABI is unchanged.

## New models

Graded by the parity suite against each model's ideal-fp16 ceiling, on an M1 Max with macOS 27. Bold marks the path each model is served on:

| model | format | served on | CPU | GPU | Neural Engine |
|---|---|---|---|---|---|
| laya-typed-decisions (laya at 1,024 tokens) | laya | ANE | D | A | **C** (2.14× ceiling, no flips) |
| GLiNER2.5-Decide | gliner2 (new) | GPU | D | **A** (1.14× ceiling) | C, and 10–40× slower |
| Julia-1, **preview** | laya, Julia rendering (new) | ANE | D | C | **C** (7 flips of 2,510) |

- **laya-typed-decisions** handles inputs up to 1,024 tokens. Its 30 long test cases stay accurate on every path.
- **GLiNER2.5-Decide is served on the GPU.** On the Neural Engine its DeBERTa attention rewrite is slow and less accurate. Its first request per bucket takes seconds while the bucket loads.
- **Julia-1 stays a preview.** It passes every gate, but decision flips cap both of its fp16 paths at C. fp16 rounding alone flips two of its decisions.
- **Parity, not accuracy.** fast-decisions is fastino's own benchmark, and Julia-1's training data is private, so every model is graded against its own fp32 output, never for accuracy.

## laya-en: supported, exactly bucket-invariant

laya-en's converter now builds every softmax from exp and one matmul, which makes its Neural Engine output bit-identical across buckets. Under the new grading it passes every gate on every path: A on the GPU, and C on the Neural Engine, where one borderline flip caps an otherwise B-level result. It's served on the Neural Engine by default; `compute_units = "cpu_and_gpu"` serves its A path at about the same latency.

**When a classifier is a preview.** A classifier is supported when it passes every hard gate on every path, converts exactly in fp32 with no known unfixed defect, and grades A on at least one path. Otherwise it's a preview. By that rule, laya-en, laya-typed-decisions and GLiNER2.5-Decide are supported, and Julia-1 is a preview.

## Grading against the ideal-fp16 ceiling

Some classifiers make decisions finer than fp16 can represent, so even a perfect fp16 conversion of laya could never grade above D on the absolute scale. Each classifier reference now carries an ideal-fp16 oracle (`sidekick_convert.fp16sim`), and the suite grades each path by its p99 error relative to that ceiling: A ≤ 1.25×, B ≤ 2×, C ≤ 4×. The better of this and the absolute grade counts. On the GPU and Neural Engine, variation between buckets within the ceiling passes the bucket gate. Details are in the D28 amendment and [docs/MODELS.md](https://github.com/ironblock/sidekick/blob/v0.5.0/docs/MODELS.md#classifiers-v1classify).

## Conversion tools

- **Every converter now runs on the conversion library.** Rebuilt through it, all seven models from 0.4 are byte-identical.
- **New library modules:** DeBERTa-v3 with a gather-free relative shift, the gliner2 and Julia converters, and laya's converter generalized to laya-typed-decisions (`--model`, `--laya-code`).
- **Fixed: a coremltools crash in every converter's gates.** Predicting on a temporary input could crash Python about a second later. The library now keeps prediction inputs alive.
- **New in `docs/CONVERTING.md`:** two Core ML defects. A coremltools input-lifetime crash, and the fused attention op's CPU crash at head dim 16, which the library never emits.
