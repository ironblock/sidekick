sidekick v0.7.1 stops a model's first request from timing out while its bucket compiles, and fixes the largest source of Neural Engine error in sidekick's SiLU models: agent-jev's ANE path goes from grade D to B, and Lumma-fev's and F2LLM's ANE error shrinks.

## Upgrading

- **Reconvert agent-jev, Lumma-fev-0.1b and F2LLM-v2-160M** to get their smaller Neural Engine error. The converters change; the runtime doesn't. Artifacts converted with 0.7.0 keep working at their old grades.
- **New daemon config key:** `load_timeout_secs` (default 900). A 0.7.0 daemon refuses to start with a config that sets it, since its config rejects unknown keys.
- **New error code:** `load_timeout` (504, with `Retry-After: 30`), when a model is still loading after `load_timeout_secs`. The `timeout` code keeps its meaning, a request that didn't complete in time, and its message now names the work ("Classification", "Embedding", "Reranking") instead of "Generation".
- **Rust API:** additions only. `Classifier::load_buckets` and `Embedder::embed_staged` are new trait methods with default bodies, so existing implementors compile unchanged. `BucketModels::ensure` is new, and the server's `Config` gains `load_timeout_secs`. The HTTP API only adds an error code, and the C ABI is unchanged.

## A model's first request no longer times out while it loads

A bucket's first load compiles it for this Mac's Neural Engine or GPU: seconds for a small bucket, minutes for a large one (about 47 s for laya-typed-decisions' 1,024-token bucket on an M1 Max, about 4 minutes for agent-jev's 2,048). The request timeout (`request_timeout_secs`, default 60) used to cover that compile, so a cold request could return 504 while the load finished in the background.

- **Loading is now bounded separately,** by `load_timeout_secs` (default 900). This covers the model, its buckets, and a request waiting on another request's load of the same bucket.
- **The request timeout bounds the prediction only,** counted from when loading ends. A hung prediction still times out.
- **Either timeout abandons the wait, not the work.** A load still finishes and stays resident, so a retry is fast.

This applies to the classify, embeddings, rerank and v2 embed routes; chat is unchanged. Loading every bucket at startup is a possible follow-up (#58).

## The Neural Engine's SiLU (D39)

Core ML's SiLU on the Neural Engine was the dominant error in agent-jev's grade on that path. The fix is a SiLU form that doesn't cancel in fp16 for either sign of its input, StableSilu: `2x·exp(min(x,0)) / (1+exp(−|x|))`. It also beats TanhSilu, the form sidekick used before, which cancels for large negative inputs. Its exact form costs 12–15% of ANE time.

| model | ANE before | ANE after | GPU | ANE ms |
|---|---|---|---|---|
| agent-jev (chunked) | D (4.2× its ideal-fp16 ceiling, worst \|Δp\| 0.022) | **B** (1.44×, worst 0.0056, no flips) | A | 128 → 152 |
| Lumma-fev-0.1b | B (1.57×, worst 0.010) | B (1.43×, worst 0.0057, under the ceiling's own worst) | A | 33 → 37 |
| F2LLM-v2-160M | A (worst 1−cos 2.8e-5) | A (worst 0.7e-5) | A | 4.6 → 5.3 |

Measured on an M1 Max with macOS 27, with each model's full parity corpus.

- **Where it helps.** StableSilu helps where a SiLU sees large negative inputs. It made no measurable difference to LFM2.5, whose converter already rescales the SiLU's inputs, so LFM2.5's converter is unchanged.
- **Input rescales** helped only where a linear layer's inputs sit under the ANE's small-input precision floor: agent-jev's layers, and F2LLM's MLP output projection.
- **Measure in-model.** A lone `silu` isn't placed on the Neural Engine, so activation forms have to be compared inside the model.

The details are in D39 and [docs/MODELS.md](https://github.com/ironblock/sidekick/blob/v0.7.1/docs/MODELS.md).

## agent-jev on the Neural Engine: chunk it

The other route under the Neural Engine's weight limit for agent-jev, one program per bucket with an int8 token embedding (`--int8-embedding --chunks 1`), was graded with the same rewrite. The chunked build is better:
- it keeps the GPU's A (int8: B);
- its ANE error is lower (1.44× against 1.74× the ceiling);
- it has room under the limit (0.57 GiB per program against 0.97–0.99).

The int8 build is a few percent faster only at the longest buckets, and Core ML produced no compute plan for its 2,048-token bucket. agent-jev stays GPU-served by default; the chunked Neural Engine path is the operator's option (D38).
