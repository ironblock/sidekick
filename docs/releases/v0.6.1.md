sidekick v0.6.1 makes agent-jev a supported model: its CPU path, which depended slightly on the bucket an input landed in, is now exact, and the parity suite reports rather than grades a Neural Engine path the runtime won't serve.

## Upgrading

- **Reconvert agent-jev** with this release's `tools/convert_agentjev.py` to get exact bucket invariance. Artifacts converted with 0.6.0 keep working on the GPU, where agent-jev is served, at the same grade.
- No API or configuration changes. The daemon, the HTTP API, the Rust API and the C ABI are the same as 0.6.0's, apart from one new public helper in `sidekick_core`, `ane_weight_refusal`.

## agent-jev: supported

agent-jev's CPU results differed slightly between buckets even below 1,024 tokens, where the CPU limit (D33) doesn't apply: up to |Δp| 0.019 for the same input in its 512 and 1,024 buckets. That kept it a preview.

- **The cause** is Core ML's CPU softmax. When it reads an attention score matmul's output in the same program, it rounds differently for different key lengths. `tools/repro_cpu_softmax_length.py` reproduces it standalone. Lumma-fev was never affected, because its converter already computes the softmax with a matmul.
- **The fix** gives agent-jev's converter the same matmul softmax. It's exact in fp32, and the CPU's buckets now agree exactly up to 1,024 tokens. On the GPU, where agent-jev is served, the buckets became exact too.
- **Grades** (2,627 cases, M1 Max, macOS 27, against the ideal-fp16 ceiling): GPU **A** (p99 at 0.85× the ceiling, was 0.70×; worst |Δp| 3.2e-3, was 4.2e-3; no flips; gold agreement equal to fp32's), CPU D on accuracy, and the Neural Engine path reported, not graded.

Every hard gate passes on every path, so agent-jev is supported under the preview rule. Details are in the D36 amendment and [docs/MODELS.md](https://github.com/ironblock/sidekick/blob/v0.6.1/docs/MODELS.md).

## Parity suite

A Neural Engine path the runtime refuses to serve, because the model is over the Neural Engine's weight limit (D32) and doesn't opt out, is now measured and reported instead of graded. Core ML runs such a model on the CPU, so grading it as the Neural Engine measured the wrong device. A model with `ane_weight_limit = "ignore"` is graded as before.
